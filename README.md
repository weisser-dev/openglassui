# OpenGlassUI

A local control center for coding agents, with an experimental web interface for Meta Ray-Ban Display glasses. OpenGlassUI runs a companion service on your computer: configure your workspace and agents there, then use the desktop dashboard or a paired glasses web app to follow tasks and respond to supported questions.

> **Status: early prototype.** Local Codex task creation, continuation, and an interactive multiple-choice question have been exercised with a real Codex installation. Claude Code's real end-to-end flow, the Meta AI installation link, the wristband, and WebMCP have **not** been verified on physical glasses. Do not treat the current remote-access design as production-ready.

## What works today

| Capability | Current implementation | Limits |
| --- | --- | --- |
| Local dashboard | Start and stop tasks, view output, and continue supported sessions | The current interface and agent instructions are in German |
| Codex | Local app-server adapter, output, session browser, follow-up turns, supported questions and one-time approvals | Uses the experimental `default_mode_request_user_input` flag; supported request types and Codex versions may change |
| Claude Code | Claude Agent SDK adapter, session browser, follow-up turns, question and permission callbacks | Adapter flows have automated tests with a simulated SDK. A real run failed because the test machine's OAuth session had expired; reauthentication and end-to-end validation are still needed |
| Kiro CLI | Example configuration for a noninteractive task using stdin | Not verified end to end; no session browser, resume, or interactive approvals |
| Other CLIs | Configurable command and arguments; prompts are sent via stdin without a shell | The program must accept stdin. Output is raw; there is no generic session discovery or interactive decision support |
| Glasses and voice | Experimental glasses page, one-time pairing QR, directional-key handling, and WebMCP tools | Requires an HTTPS tunnel; device installation, gesture handling, dictation, and Meta AI availability are unverified |

For new Codex and Claude tasks, the adapters ask the agent to present concise options when user input is needed. Suggestions are generated by the agent from its available context and are not guaranteed for every question. Explicit approvals are presented separately and are not automatically granted.

## How it fits together

```text
Desktop browser ────────────┐
                            ├── local companion (127.0.0.1:4173)
Glasses web app ── HTTPS ───┘       ├── Codex app-server
                  tunnel             ├── Claude Agent SDK
                                     └── configured stdin-based CLI
```

The companion owns the workspace and agent configuration, launches agents locally, and stores task data on the computer. The glasses page communicates with that companion through a separately configured HTTPS tunnel. The QR code is an installation and pairing link; it does not create the tunnel.

## Requirements

- Node.js 20 or later and npm.
- A supported agent installed, authenticated, and available to the local user. Codex requires the `codex` executable; the Claude adapter uses the Claude Agent SDK and its supported authentication. Verify your provider's current authentication and usage requirements.
- For glasses: Meta Ray-Ban Display, an iPhone with the Meta AI app, access to the necessary developer/web-app settings, and a public HTTPS endpoint connected to the companion.
- For the example tunnel below: [cloudflared](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/).

Meta's device capabilities, developer settings, and WebMCP availability may vary by account, region, firmware, and rollout. A desktop browser test does not verify device behavior.

## Local setup

Clone the repository and install dependencies:

```sh
git clone https://github.com/weisser-dev/openglassui.git
cd openglassui
npm ci
```

Create a local configuration from the example and adjust it for your machine:

```sh
cp config.example.json config.json
```

On Windows, copy `config.example.json` to `config.json` using Explorer or your shell. Alternatively, `./setup.sh` on macOS/Linux or `setup.bat` on Windows installs dependencies and creates the configuration if it does not already exist. These scripts are not signed native installers.

Set `workspace` to the project the agents should work in. A relative path is resolved relative to the configuration file. Configure the agent IDs, executable names, and arguments under `agents`; `config.json` is ignored by Git. Agent sign-in, provider settings, and permission policies remain the responsibility of the respective tools.

Start the companion:

```sh
npm start
```

Open [http://127.0.0.1:4173](http://127.0.0.1:4173). The dashboard also contains a step-by-step glasses installation guide. Use **Bestehende Sitzungen** to browse up to 50 Codex or Claude sessions belonging to the configured workspace. Only continue sessions that are no longer active elsewhere; attaching safely to an externally running session is not supported.

### Configuration details

`config.example.json` provides Codex, Claude Code, and Kiro examples. For a custom CLI, add an object with `id`, `name`, `command`, an `args` array, and `input: "stdin"`. The configured command receives the task through stdin and is started with `shell: false`. Only install or configure executables you trust: these agents run with the local user's privileges and their own permission settings.

Codex and Claude are special adapters selected by the IDs `codex` and `claude`; they do not use the generic CLI path. Codex uses `command` to start its app-server. Claude is launched through the Agent SDK rather than the configured `command`. The current server still requires valid `args`, `input`, and `command` fields for both; `resumeArgs` must be present for the resume action to be offered. Changing those CLI argument arrays does not configure the special adapters. Other CLI entries use the generic command and arguments and currently have no way to discover a session ID for resume.

Optional environment variables:

| Variable | Purpose | Default |
| --- | --- | --- |
| `PORT` | Local HTTP port | `4173` |
| `OPENGLASS_CONFIG` | Path to a JSON configuration file | `config.json` in the project directory |
| `OPENGLASS_DATA_DIR` | Directory for local task data | `.openglass/` in the project directory |

The service binds to `127.0.0.1`, not the local network. Tasks and their output are written to `.openglass/tasks.json` by default, including prompts and potentially sensitive agent output. Data is not encrypted at rest. Running tasks are marked interrupted after a server restart.

## Connect the glasses (experimental)

1. Enable the developer/web-app options required by Meta AI for your glasses.
2. Start OpenGlassUI and leave it running on the computer.
3. In a second terminal, create an HTTPS tunnel. For example, with cloudflared installed and the default port:

   ```sh
   cloudflared tunnel --url http://127.0.0.1:4173
   ```

   Copy the HTTPS URL printed by cloudflared. If you changed `PORT`, use that port in the command. Cloudflare describes Quick Tunnels as a development feature; the address changes when the tunnel is restarted. See the [Quick Tunnel documentation](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).
4. In the desktop dashboard, paste that address into **ÖFFENTLICHE HTTPS-ADRESSE** and choose **Kopplungscode erzeugen**.
5. Scan the QR code with the iPhone, follow the Meta AI app's add-web-app flow, and open OpenGlassUI on the glasses **within five minutes**. The pairing code can be redeemed once. This deep-link flow is implemented but has not been verified on the actual device.
6. Keep the companion and tunnel running while using the app. An Internet connection is needed for the tunnel; the glasses and computer do not need to be on the same LAN when the HTTPS endpoint is reachable.

The glasses page supports keyboard-style directional navigation and Select. It also registers experimental WebMCP tools when `document.modelContext` is available. Whether the glasses expose these tools to Meta AI, support dictation, or route wristband inputs as expected needs a real-device test.

## Security and privacy

**This is an experimental single-user prototype, not a hardened remote-access service.**

- The companion binds to localhost. Remote access depends on a correctly configured HTTPS reverse proxy. The current local/remote distinction relies on the `Host` and forwarding headers: a proxy must reliably set `X-Forwarded-For`, `CF-Connecting-IP`, or `Forwarded`. A proxy that omits or mishandles those headers can expose local-only operations. Do not expose the service directly or assume any arbitrary proxy is safe.
- A pairing QR contains a short-lived secret. Anyone who redeems it can read accessible tasks and sessions and launch configured agents with the permissions of the local user. Treat the QR and installation link like a password; do not share screenshots or logs containing them.
- The companion issues a bearer token to a paired device. It is stored in that device's browser storage, is not device-bound, and remains valid until revoked or the server restarts. Use **Alle Verbindungen trennen** in the local dashboard to revoke all tokens. Re-pair after a restart; the current UI has no individual-device management.
- Remote task data and agent outputs pass through the HTTPS tunnel provider. Local task data is stored without encryption. Consider what code, prompts, and output the agent and tunnel provider can access.
- Approvals are per request where supported. Existing agent configuration may already allow actions without a prompt. OpenGlassUI does not guarantee a separate confirmation for every action.

## Current technical gaps

- **Physical device validation:** QR deep link, setup, layout, focus order, wristband gestures, text input, WebMCP, reconnection, and long-running use need testing on actual Meta Ray-Ban Display hardware.
- **Installation and hosting:** No native signed installer, integrated tunnel provisioning, stable hosted URL, automatic updates, or background service. HTTPS and any reverse-proxy access control must be configured separately.
- **Sessions:** No reliable live takeover of sessions running in other clients, no pagination beyond the first 50 sessions, and no full transcript navigation or search. Generic CLI and Kiro sessions cannot currently be resumed through the app.
- **Questions and permissions:** No complete multi-select handling or queue for simultaneous requests. Additional concurrent permission requests are denied rather than queued. Not every Codex server-request type is supported. AI-generated choices depend on the agent and may be absent.
- **Security:** No per-device identity or revocation, encrypted credential/data storage, token renewal across server restarts, granular authorization, formal security review, or production-grade proxy authentication. The current deployment must remain a trusted, experimental single-user setup.
- **Reliability and UX:** No multi-workspace picker, agent health checks, task deletion, rich structured event timeline, reliable child-process-tree termination, comprehensive accessibility testing, or English UI. Outputs are bounded and may be truncated.
- **Testing:** Automated tests use a simulated Codex server and Claude SDK for decision paths; they do not validate a real Claude account, every supported CLI, a live tunnel, WebMCP, or the glasses.

## Tests

```sh
npm test
```

The suite exercises the local API with a test agent, pairing and revocation, and simulated Codex and Claude decision handling. It requires permission to bind a localhost port. A successful suite is not a substitute for hardware or provider end-to-end testing.

If Claude reports that its OAuth session has expired, authenticate again using the supported Claude Code login flow, for example `claude auth login` where available, then retry. OpenGlassUI does not request or store your Claude password.
